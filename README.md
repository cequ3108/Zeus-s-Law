# 宙斯法則

在台灣提供或請求幫助的小網站。食物、交通，或其他需要都可以。沒有現金換手。功德在人之間流動，1 功德等於 1 元新台幣，但不能兌換現金。

這是給大約一千人使用的第一版：一個 Node.js 程序、一個 SQLite 檔案。之後可以放到有持久磁碟的免費主機，不需要另外的資料庫服務。

## 本地執行

需要 Node.js 22 以上。

```bash
npm install
npm start
```

瀏覽器打開 <http://localhost:3000>。

開發時可以改用 `npm run dev`，存檔後會自動重啟。

資料存在 `data/zeus.db`。這個檔案不會進版本庫。想重來，把伺服器停掉再刪掉它。

執行測試：

```bash
npm test
```

想先看到縣市、今日空檔、一筆已結算的互助，可以灌示範資料。這不會建立創辦人，也不會在重跑時把餘額再加一次：

```bash
npm run seed:demo
```

示範帳號（只供試用）：

- 阿明 `0918000001`，密碼 `demo-aming-1`
- 阿花 `0918000002`，密碼 `demo-ahua-2`

備份資料庫：

```bash
npm run backup
```

檔案會寫到 `backups/zeus-<時間>.db`。若設定了 `DATA_DIR`，則寫到該目錄下的 `backups/`。`BACKUP_DIR` 可以另外指定。`backups/` 不會進版本庫。

## 第一階段已加上的功能

這些都不改結算公式。功德仍在結算當下移動，同一對帳號同一天仍只能結算一次。

- 手機底部有四個分頁：首頁、發文、我的交易、我的帳號。
- 新貼文要選縣市，行政區可以不填。首頁可篩選；帳號有縣市時，首頁預設看那個縣市。沒填縣市的舊貼文留在「全部」。
- 發文模板：便當、共乘、陪看病、代買。會帶出標題、描述和建議區間。福利機構看不到「我可以提供」的模板。
- 金額旁有估價提示。同一個種類與縣市若有結算紀錄，就用那些數字；否則用模板區間。寫了現金、轉帳給我、匯款、付錢會被拒絕。畫面上寫明約 1 元價值、僅供估價參考，以及功德不可購買、兌現或轉售。
- 新貼文預設 48 小時後從廣場消失，也可選 24 或 72。過期的舊狀態不變，發布者可以一鍵重發。沒有期限的舊貼文仍看得到。
- 配對後提示約在便利商店或捷運站，並可用 LINE 分享連結把對方稱呼、星等、幫過次數、時間地點傳給朋友。沒有 LINE 機器人。
- 個人頁有信譽：幫過幾次、被幫過幾次、星等、徽章。徽章不另發功德。
- 今日空檔可寫在帳號頁，並出現在個人頁與貼文旁。
- 本週功德進出（支出、收入、額度增加）只在自己的帳號頁。公開個人頁看不到。
- 每一次功德移動寫進只追加的帳本。不能修改或刪除。創辦人的管理頁看得到最近紀錄。
- 沒有接上付費簡訊時，用手機號碼加密碼自助註冊。創辦人由 `FOUNDER_PHONE` 與 `FOUNDER_PASSWORD` 在啟動時建立。

還沒做、等創辦人決定下一階段的：有意願佇列、託管、見面碼、24 小時確認期限、一小時提醒、再次互助、追蹤通知、新手任務、每週主題獎金、感謝牆、捐功德、機構多名額、檢舉、邀請碼、在地大使。

## 開發模式：密碼，或畫面上的驗證碼

沒有設定 `SMS_PROVIDER=every8d` 時，程式不會呼叫簡訊商，也不會假造一組金鑰。這時可以用手機號碼當帳號，自己設定密碼來註冊與登入。密碼以 Node.js 內建的 scrypt 做成雜湊後才寫進資料庫，不明文存放。

同一種環境下，簡訊驗證碼仍會直接顯示在驗證頁，既有的驗證碼登入可以繼續用。頁首會標成示範站。伺服器記錄只會寫「驗證碼顯示在登入頁」，不會把驗證碼或密碼寫進記錄。

接上 EVERY8D 之後，新帳號改走簡訊驗證碼。已經設過密碼的帳號（包含創辦人）仍可用密碼登入。

## 創辦人與福利機構

公開註冊只會建立一般使用者，功德額度與功德都是 100。沒有創辦人或機構的註冊選項。

在主機設定這兩個環境變數後啟動，第一次會自動建立創辦人，功德與額度都是 100,000,000：

```bash
FOUNDER_PHONE=0912345678
FOUNDER_PASSWORD=一組只有你知道的密碼
```

兩個都要有。只填一個時不會建立，伺服器會留下警告。這個手機若已經是一般使用者或機構，不會被改成創辦人，餘額也不會動。已經是創辦人時，再次啟動只更新密碼雜湊，不會把餘額補回一億。

也可以用種子指令建立創辦人，再用上面的環境變數補上密碼：

```bash
npm run seed:founder -- 0912345678 創辦人
```

然後用這個號碼與密碼登入。開發模式也可以改走畫面上的驗證碼。創辦人可以在「管理」頁：

- 用手機號碼直接建立福利機構，或把現有的一般使用者升為機構
- 審核一般使用者送出的機構申請
- 封鎖收取現金的帳號，或解除封鎖

福利機構的功德與額度是 1,000,000。機構只能發布「我需要」。

再執行一次種子指令不會把創辦人的餘額補回去，避免變成鑄造功德的方法。

## 接上 EVERY8D

簡訊只從 `src/sms.js` 送出。要改接時，設定環境變數，不要把帳號密碼寫進程式或版本庫：

```bash
SMS_PROVIDER=every8d
EVERY8D_UID=你的帳號
EVERY8D_PWD=你的密碼
# 選填，預設是 EVERY8D 的 SendSMS 位址
EVERY8D_API_URL=https://api.e8d.tw/API21/HTTP/SendSMS.ashx
```

可以參考 `.env.example`。這個程式不會自動讀 `.env`，啟動前請自己匯出變數，或由主機的環境設定帶入。

若指定了 `every8d` 卻沒有帳號或密碼，發送會失敗，不會偷偷改回開發模式。

正式環境另外請設定：

```bash
NODE_ENV=production
SESSION_SECRET=一長串隨機文字
DATA_DIR=/你的持久磁碟/zeus-data
```

`DB_PATH` 若有設定，會蓋過 `DATA_DIR`。登入狀態存在同一個 SQLite 檔的 `sessions` 表，重啟或主機休眠後不會被清掉。程式信任前面一層反向代理：請求帶 `X-Forwarded-Proto: https` 時，cookie 會加上 Secure。直接開 `http://localhost:3000` 時不加 Secure，本機仍可登入。

## 放到有持久磁碟的免費 Node 主機

程式以 `npm start` 啟動，聽 `PORT`（沒有設定時是 3000）。資料庫是單一 SQLite 檔，預設寫在 `DATA_DIR/zeus.db`。主機必須有持久磁碟；沒有磁碟的免費方案在休眠或重新部署後會把帳號與功德清掉。

建議用 [Bonto](https://bonto.dev/register)。用 GitHub 登入後，拉取這個公開倉庫的分支，Node 22，啟動指令 `npm start`。若用 nodemon，專案裡的 `nodemon.json` 會忽略 `data/` 與 `backups/`，資料庫寫入不會把程序重啟。不要設定 `SMS_PROVIDER`。把資料目錄指到主機不會清掉的磁碟。

要設定的環境變數：

| 變數 | 要不要設 | 作用 |
| --- | --- | --- |
| `PORT` | 主機通常自己帶 | 網站聽的埠 |
| `SESSION_SECRET` | 要 | 登入 cookie 的簽名。用一長串隨機文字 |
| `DATA_DIR` | 要 | SQLite 所在目錄，指到持久磁碟，例如 `/data` |
| `DB_PATH` | 不必 | 直接指定資料庫檔。有設的話會蓋過 `DATA_DIR` |
| `FOUNDER_PHONE` | 要 | 創辦人手機，09 開頭共 10 碼 |
| `FOUNDER_PASSWORD` | 要 | 創辦人密碼，8 到 64 個字。只會存 scrypt 雜湊 |
| `NODE_ENV` | 選填 | 不決定 cookie。HTTPS 由代理的 `X-Forwarded-Proto` 判斷 |
| `SMS_PROVIDER` | 先不要設 | 不設就能用手機加密碼註冊。設 `every8d` 才會送簡訊 |
| `EVERY8D_UID` | 接簡訊才要 | EVERY8D 帳號 |
| `EVERY8D_PWD` | 接簡訊才要 | EVERY8D 密碼 |
| `EVERY8D_API_URL` | 選填 | 預設是 EVERY8D 的 SendSMS 位址 |

不要把 `FOUNDER_PASSWORD`、`SESSION_SECRET` 或簡訊密碼寫進版本庫。`.env` 已被忽略。範例在 `.env.example`，裡面只有空的占位。

部署後用自己的手機在登入頁「建立帳號」，會得到一般使用者 100／100。再用 `FOUNDER_PHONE` 與 `FOUNDER_PASSWORD` 登入，應看到創辦人與 100,000,000。

## 產品規則

### 帳號

- 用台灣手機號碼當帳號。沒有接上付費簡訊時，以密碼註冊與登入。接上簡訊後，新帳號以驗證碼確認。不存放身分證或護照。密碼只存 scrypt 雜湊。
- 三種角色：一般使用者、福利機構、創辦人。
- 新的一般使用者：功德額度 100、功德 100。1 功德等於 1 元新台幣。
- 創辦人：兩者都是 100,000,000。由 `FOUNDER_PHONE` 與 `FOUNDER_PASSWORD` 在啟動時建立，或用種子指令設定。不是公開註冊。再次啟動不會把餘額補回去。
- 福利機構：兩者都是 1,000,000。不是公開註冊。創辦人可以直接建立，或審核申請後通過。

### 發布

- 雙方都可以發布。「我可以提供」或「我需要」，描述必填，並標示一個新台幣金額（功德）。
- 福利機構只發布「我需要」。幫忙的人獲得功德，由機構付出。
- 一般使用者若是付出功德的一方（接受幫助的人），功德減去標示金額後必須大於 0，才能接下或被配對。例如 100 功德不能接標示 200 的貼文，因為會變成 -100。餘額不允許變成負數。剛好扣到 0 也不行接，因為扣完必須大於 0。
- 提供幫助的人是收入功德，不受上一條限制。否則機構無法把較大的金額付給只有 100 功德的幫手。
- 被封鎖的人不能發布，也不能接下。

### 結算

- 互助完成後，雙方各自填寫認為值多少新台幣。結算金額是較低的那個。任一方填 0，結算就是 0。
- 功德額度只增不減。雙方額度都加上結算金額。
- 功德的移動：接受幫助的人支出結算金額，提供幫助的人收入。福利機構的需要，機構是支出的一方，幫手是收入的一方。
- 同一對帳號在台北時間的同一個日曆日最多結算一次。這一次也是當天彼此額度唯一會增加的時候。隔日再做一次是允許的，額度會再增加。這是規則，不是漏洞。同一天跟不同的人結算，各自算一對。
- 填 0 也算用掉當天這一次。
- 若結算會讓付出的一方變成負數（包含機構功德不夠），這則不能完成，餘額維持原狀。可以改填較低的金額。
- 依這些規則，功德不會超過額度。沒有另外鑄造功德的功能。

### 星等與現金

- 結算後雙方互相給 1 到 5 顆星。星等顯示在個人頁，雙方與其他人都看得到。
- 評分可以留下備註。備註會存進資料庫，但畫面不顯示，連留下的人自己也看不到。
- 平台禁止現金。頁面上有固定標示。創辦人可以因收取現金封鎖使用者。被封鎖的人不能發布或接下。
